## Gotchas

- **V2 is the default storage architecture for new installs**, but V1 names and docs remain throughout the repo. Ingester, querier, and store-gateway still appear in config flags, API paths, metrics, and the V1 architecture doc tree. Do not infer current deployment defaults from those residues alone.
- **`operations/pyroscope/helm/pyroscope/values-micro-services.yaml` is not the chart default.** It uses the legacy top-level `pyroscope.components` override path (V1 component names such as ingester and store-gateway) and does not set `architecture.microservices.enabled`. The current chart structure lives under `architecture.storage` and `architecture.microservices.v1` / `.v2` in `values.yaml`. User-facing install docs must follow `values.yaml` and chart templates (`templates/_helpers.tpl`), not this auxiliary file.
- **Grafana Agent was replaced by Grafana Alloy in the Helm chart defaults.** Legacy `agent.enabled` and `values-micro-services.yaml` paths still exist in the repo; default install behavior is in `operations/pyroscope/helm/pyroscope/values.yaml`.
- **`docs/sources/reference-pyroscope-architecture/` is the V1 (legacy) architecture tree.** Current architecture docs live under `docs/sources/reference-pyroscope-v2-architecture/`. Keep V1 and V2 pages distinct; do not merge their write/read paths in new prose.
- **`docs/sources/get-started/_index.md` still links to V1 deployment modes.** That page describes monolith startup and points at `reference-pyroscope-architecture/deployment-modes/`. For current install defaults and V2 architecture, use `docs/sources/deploy-kubernetes/` and `docs/sources/reference-pyroscope-v2-architecture/`.
- **Symbolizer is opt-in and not in the V2 component doc tree.** `-symbolizer.enabled` defaults to `false` (`pkg/validation/symbolizer.go`). Symbolizer options appear in the generated configuration reference and release notes, but there is no component page under `reference-pyroscope-v2-architecture/components/`.
- **`docs/sources/shared/use-explore-profiles.md` may lag the Profiles Drilldown app.** For UI behavior and terminology, cross-check `[upstream]` [grafana/profiles-drilldown](https://github.com/grafana/profiles-drilldown) (`docs/sources/` there) when validating explore/drilldown claims.

## Do-not-edit paths

- **`docs/sources/configure-server/reference-configuration-parameters/index.md`** — generated from `index.template` (see banner in file). Edit the template and source config in `pkg/` / `cmd/pyroscope/`; regenerate with `make generate`.
- **`docs/sources/reference-server-api/index.md`** — generated from `index.template` by `tools/api-docs-generator/` during `make generate`. Edit the template and API sources; do not edit the output file by hand.
- **`cmd/pyroscope/pyroscope.yaml`** — example server config generated by `make generate` from the configuration reference template. Edit via the template and config structs, not by hand.
- **No generated Helm values reference page.** Document Helm options as prose in `docs/sources/deploy-kubernetes/`; chart defaults live in `operations/pyroscope/helm/pyroscope/values.yaml`. The chart README under `operations/pyroscope/helm/pyroscope/` is generated separately via `make helm/docs`.
- **`operations/pyroscope/jsonnet/values-micro-services.json`** and **`values-micro-services-hpa.json`** — generated from the Helm values files of the same names during `make helm/check` in the root `Makefile`. Edit the YAML sources, not the JSON, unless you are intentionally updating generated artifacts as part of a chart change.
